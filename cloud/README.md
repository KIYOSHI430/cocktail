# 数据上云 · 部署手册（PostgreSQL 版）

环境 ID：`cocktail-d1gk02vdl123a2e05`

你的环境用的是**云开发新版控制台 + PostgreSQL 数据库**，所以下面按这个来。全程在控制台里点，不需要改代码。

整个过程四步：**① 建表 → ② 导数据 → ③ 部署云函数 → ④ 开通 HTTP 网关**。

---

## 第一步：建表（执行 01-schema.sql）

1. 左侧点「**SQL 型数据库**」
2. 左侧子菜单点「**SQL 编辑器**」
3. 打开项目里的 `cloud/sql/01-schema.sql`，**全选复制**，粘进 SQL 编辑器
4. 点「**执行**」

执行完点左侧「**表**」，应该能看到 8 张表：`users` `sessions` `ingredients` `recipes` `comments` `posts` `reports` `settings`

---

## 第二步：导数据（依次执行 02 → 05）

还是在 SQL 编辑器里，**一个一个来**（每次粘贴一段、执行一次）：

| 顺序 | 文件 | 内容 |
| --- | --- | --- |
| 1 | `cloud/sql/02-ingredients.sql` | 192 种材料 |
| 2 | `cloud/sql/03-recipes-1.sql` | 配方第 1 批 |
| 3 | `cloud/sql/04-recipes-2.sql` | 配方第 2 批 |
| 4 | `cloud/sql/05-accounts-posts.sql` | 管理员账号、示例帖与评论、站点设置 |

> 03 和 04 是两个较大的文件（各 40KB 左右），如果编辑器卡，可以拆成两半分次执行；语句都是 `insert ... on conflict do nothing`，重复执行也不会出错。

**验证**：SQL 编辑器里跑一句

```sql
select (select count(*) from ingredients) as 材料,
       (select count(*) from recipes) as 配方,
       (select count(*) from users) as 账号,
       (select count(*) from posts) as 帖子;
```

应该返回 **192 / 115 / 2 / 2**。

---

## 第三步：部署云函数 `api`

> **注意**：云开发新版控制台的 SQL 数据库**不给连接串**，而是用 SDK 的 `rdb()` 接口访问
> （就是「接入指引 → 后端框架 → Node.js」里那段代码）。云函数已经按这个方式写好了，
> **不需要配连接串、也不需要配密钥** —— 云函数运行时会自动带上环境凭据。

### 1. 建云函数

1. 左侧「**云函数/托管**」→「**新建云函数**」
2. 函数名填 **`api`**，运行环境选 **Node.js 18**
3. 代码来源选「在线编辑」，把项目里 `cloud/api/index.js` 的**全部内容**粘进去
4. 依赖里加上（`package.json`）：

   ```json
   { "dependencies": { "@cloudbase/node-sdk": "latest" } }
   ```

5. 点「**保存并安装依赖**」，等依赖装完（这会自动装好 SDK，不用你手动装）

### 2. 测试

点「**测试**」，事件内容填：

```json
{ "action": "ping" }
```

- 返回 `{"ok":true,"data":{"db":"ok",...}}` → **数据库通了**，成功
- 返回 `数据库连不上：...` → 把完整报错发我，我看是接口调用方式要调整

---

## 第四步：开通 HTTP 网关

1. 左侧点「**HTTP 网关**」
2. 新建一条路由：**路径 `/api`**，指向云函数 **`api`**
3. 保存后你会拿到一个地址，形如：

   ```
   https://cocktail-d1gk02vdl123a2e05.service.tcloudbase.com/api
   ```

4. **在浏览器里直接打开**（注意带上参数）：

   ```
   https://cocktail-d1gk02vdl123a2e05.service.tcloudbase.com/api?action=ping
   ```

   看到 `{"ok":true,...}` 就说明**整条链路通了**。把这个地址发我，我把前端切到云端。

---

## 完成后是什么状态

- 数据库里有 192 种材料、115 款配方（含材料明细、步骤、标签）
- 管理员账号 = 你的手机号，密码是 **scrypt** 哈希（连数据库里都看不到明文）
- 前端只能通过云函数读写，数据库本身不对公网开放
- 登录发 token 存 `sessions` 表，30 天有效

---

## 安全建议（上线前做）

1. **数据库不要开公网访问**（用内网连接，云函数与数据库同环境）
2. 把「SQL 型数据库 → 备份」设成**每天自动备份**
3. 云函数的 `DATABASE_URL` 只放环境变量，**不要写进代码**
4. 前端切到云端后，本地那份 localStorage 就只是缓存了，可以不管它
