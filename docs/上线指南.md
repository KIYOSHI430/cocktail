## 一、现在的状态

网站是**纯前端**：代码放在 GitHub Pages 上，数据存在**每个访客自己的浏览器**里（localStorage）。

| | 现在（纯前端） | 接后端之后 |
| --- | --- | --- |
| 账号 | 每个人自己注册，只有自己这台设备认 | 全站通用，换手机也能登录 |
| 帖子 / 评论 | 你发的只有你能看到 | 所有人共享同一份 |
| 图片 | 存浏览器里，约 5MB 就满 | 存云存储，几百 MB 起步 |
| 清缓存 | 数据全丢 | 数据在云端，不受影响 |
| 密码 | 明文存在本机 | 服务端加密哈希存储 |
| 使用者 | 只能自己试 | 可以真正对外开放 |

**所以现在发给朋友，只能"体验界面"，看不到彼此的内容。**

## 二、目标架构（腾讯云开发 CloudBase）

```
浏览器（网页）
   │  HTTPS
   ▼
腾讯云开发环境
   ├── 云数据库（用户 / 配方 / 帖子 / 评论…）
   ├── 云存储（配方图、帖子图）
   ├── 云函数（AI 审核、管理员操作、发短信）
   └── 静态托管（网页本身，可绑自己的域名）
```

选它的理由：一个账号搞定数据库 + 存储 + 函数 + 托管；免费额度够开发和小规模使用；国内访问快；免备案的默认域名。

## 四、改造步骤（建议按顺序）

### 第 1 步：建云开发环境 + 数据库

1. 腾讯云控制台 → 云开发 CloudBase → 新建环境（选按量付费，前期几乎不花钱）
2. 按上面的表格建集合；`settings` 先手动填一条
3. 导入初始数据（用我写的导入脚本，或手动导入 JSON）

### 第 2 步：数据读写方式（两条路，按需选）

| 方式 | 适合 | 说明 |
| --- | --- | --- |
| **前端直连数据库 + 安全规则** | 常规读写（列表、详情、发帖、点赞） | 最省事，不用给每个功能写函数 |
| **云函数** | 敏感操作（审核、删别人的内容、发短信、调 AI） | Key 和权限都在服务端 |

安全规则示例（`posts` 集合）：

```json
{
  "read": "doc.status == 'approved' || doc.authorId == auth.uid || auth.role == 'admin'",
  "write": "auth.uid != null && doc.authorId == auth.uid"
}
```

意思是：**通过的帖子谁都能看；没通过的只有作者和管理员能看；只能改自己发的。**

### 第 3 步：把 `store.js` 换成云版本

这是关键——当初特意把数据层单独放在 `assets/js/store.js`，就是为了这一步。

界面层 `app.js` 调用的还是 `Store.addPost()`、`Store.listPosts()` 这些函数，**接口不改，只换内部实现**：

```js
// 现在（本地）
function addPost(data) { state.posts.unshift(post); persist(); }

// 之后（云端）
async function addPost(data) { return db.collection("posts").add({...}); }
```

需要注意的点：

- 有些函数要变成 **async**（`await` 返回结果），调用处加 `await` 或 `.then()`
- 列表要做**分页**（云端不会一次给你 10 万条）
- 点赞/收藏改成独立的关联集合或数组原子操作（避免并发覆盖）

我可以完整改造一遍，**界面代码基本不用动**。

### 第 4 步：图片搬到云存储

现在发帖/配方上传的图是压缩后转成 base64 存本地，改成：

```js
const res = await cloud.uploadFile({ cloudPath: "posts/xxx.jpg", fileContent: file });
// 存进数据库的是 res.fileID，展示时用 cloud.getTempFileURL()
```

好处：不占浏览器空间、多设备可见、可以配 CDN。

### 第 5 步：登录方式

| 方式 | 难度 | 说明 |
| --- | --- | --- |
| 用户名 + 密码 | ★ | 最简单，密码在云函数里用 `scrypt`/`bcrypt` 哈希 |
| **手机号验证码** | ★★ | 云开发支持短信登录；腾讯云短信按条计费（约几分钱一条），需实名 + 短信签名审核 |
| 微信登录 | ★★★★ | **网站形态个人做不了**（微信开放平台的网站应用只对企业开放，认证费 300/年）；想用微信登录就走**小程序**路线 |

个人开发者最现实的组合：**手机号验证码 + 用户名密码**。

### 现在已经写好的部分

注册/登录的前端流程已经按手机号改造完成：

- 注册：昵称 + 手机号 + 验证码 + 密码 + 确认密码（昵称可重复，手机号唯一）
- 登录：手机号 + 密码
- 验证码接口已预留：`Store.sendSmsCode(phone)` / `Store.checkSmsCode(phone, code)`

**当前是演示模式**：没有后端时，验证码直接显示在页面上（带 60 秒重发倒计时），方便先把流程跑通。

### 数据上云后要改的地方

1. **验证码交给服务端生成和校验**：前端不再生成验证码，只调用云函数；`state.smsCodes` 这段本地存储删掉
2. 部署 [`cloud/send-sms/`](../cloud/send-sms/)：填入腾讯云的 SecretId / SecretKey / 短信应用 ID / 签名 / 模板 ID
3. **加频率限制**：同一手机号 1 分钟 1 条、1 小时 5 条、同 IP 每小时 20 条 —— 防止有人刷你的短信费
4. **密码改成哈希**：现在明文存在浏览器里，上云后用 `scrypt`/`bcrypt`，服务端只存哈希
5. 手机号在数据库里建议**加密存储 + 脱敏展示**，并写进隐私政策

### 第 6 步：把 AI 审核接上

项目里已经有现成的云函数：[`cloud/review-post/`](../cloud/review-post/)，按它的 README 部署，然后把地址填到后台即可。

### 第 7 步：网页托管与域名

三种选择：

| 方案 | 成本 | 备案 | 说明 |
| --- | --- | --- | --- |
| 继续用 GitHub Pages | 免费 | 免 | 国内访问一般，代码公开 |
| **云开发静态托管** | 免费额度内 0 元 | 免（用默认域名） | 国内快，和数据库同一个环境，**推荐** |
| 自己的域名 + 云托管 | 域名约 50–80 元/年 | **需 ICP 备案**（1–3 周） | 最正式，可绑公众号/小程序 |
